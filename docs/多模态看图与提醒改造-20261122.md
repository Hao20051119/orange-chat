# 多模态看图 + 带图提醒改造说明（2026-11-22）

这次改动解决三件事：**聊天里的图片终于被真正看见了**、**代别人问话能把对方的图一起读**、**提醒能从课表/截图里自己读出时间，并且读完先跟你核对一遍**。顺带把写死在本机的 ffmpeg 路径改成了自动查找。

---

## 1. 改之前是什么样

| 场景 | 旧行为 |
|---|---|
| 私聊/群聊发一张课表图 | 只生成一句 ≤25 字的“情绪描述”，比如「满课表带来的窒息感和疲惫感」；图本身从不进模型 |
| 群聊里别人发了图（没 @ 机器人） | 模型只看到一个 `[图片]` 占位，不知道画的是什么 |
| 代传话：A 让机器人问 B，B 回一张饭图 | 回传里只有 `[对方发来一张图片]`，回给 A 的话是「他发了张图片，没正面回你」 |
| 「以后每次化学前沿课前十分钟提醒我」+ 课表图 | 提醒判定只拿到那句话，读不到课表；只能反问「几点提醒你？」，且不带图 |
| `.wxgf` 动态表情解码 | 写死 `D:\oopz\ffmpeg.exe`，换台机器就失效 |

## 2. 新增功能

### 2.1 聊天图片直接给模型看

- **私聊 / 被 @ 的群聊**：这一批里的图片解密后转成 data URI（长边 1600、JPEG q90），作为多模态 part 挂在本轮最后一条 user 消息上。文字里留一句 `[对方发来一张图片（就在下面的「图1」里：<内容描述>）]`，模型能对上“哪句话配哪张图”。
- **群聊背景**：没 @ 机器人的最近 N 条也当背景带上；其中的图同样给模型看，标成 `群图1`、`群图2`。
- **上限**：一轮最多 4 张图、base64 总量 6MB；超出的不塞图，只在文字里保留内容描述。
- **兜底**：解不出图（缺 keys、坏图、缺 ffmpeg 的 `.wxgf`）就退回文字占位，不报错、不阻塞回复。

### 2.2 图片的内容描述写进记忆

- 图片除了给模型看，还会让模型写一句**内容**描述（最长 240 字，优先抄图里的字，禁止描述电量/信号/标题栏这类装饰）。
- 这句描述会跟着入站文本写进对话记忆，以后翻历史能看到「这张图是什么」，而不是「对方发来一张图片」。
- 表情包仍然只要一句情绪描述（省钱，也不容易把表情猜错）。

### 2.3 代传话回传：把对方的文字 + 图一起看

- 收集 B 的回复时，图片/表情**存本地路径**（不存 base64，避免 queue.db 膨胀），文字存原文。
- 封口条件不变（首次回复后 5 分钟 / 满 10 条 / 60 分钟没回），封口时把「A 的问题 + B 的文字 + B 的图」拼成**一次**多模态请求，让模型自己总结再如实转述。
- 规则写进提示词：看不清就说「没看出来」、拒绝/阴阳要照实说、跟问题无关就说「没正面回你」。
- 上限：一次最多 8 张图、base64 总量 5MB。

### 2.4 提醒：粗筛 → 带图判定 → 核对 → 建单

```
入站消息（文字 / 图）
  ↓ 粗筛：委托词（提醒/记得/别忘/叫我…）或时间信号，纯寒暄不烧调用
  ↓ 把「这句话 + 这一批的图」一起交给模型（最多 3 张）
模型输出：是不是委托 / 事是什么 / 周几几点 / 周期 / 拿不准该问什么
  ↓
├─ 信息齐全、没有图          → 直接建单
├─ 缺时间（或图里读不出）     → 记「待确认」，顺口问时间（不存瞎猜的时间）
├─ 判定时真的看了图          → 记「待确认」+ 提案，问一句核对：
│                             「是不是要在每周三 13:50 提醒你化学前沿课前准备？」
│      ├─ 回「对 / 是 / 嗯」   → 按提案建单（周期、钟点一次落库）
│      ├─ 回「不对，周三 13:50」→ 按新说法重建（周期 + 钟点一起改）
│      └─ 答非所问            → 再问，问满 3 次放弃，不再纠缠
└─ 把握不足（置信度 < 0.5）   → 不建单
```

要点：

- **不再瞎猜时间**：模型自己说“不知道几点”时，它顺手填的那个时间（比如「每周一 07:50」）**不会**被存成提案；此时回「对」不会建单，只有你真给出时间才建。
- **新委托不会被当成旧答案**：等确认期间你又说「明天八点提醒我拿快递」，那是新单，不会被套成旧委托的时间和内容。
- **课表类图片**：模型会自己算提前量（14:00 上课 → 课前十分钟 = 13:50），并给出核对句。
- 候选队列（模型不可用时的兜底）也会连图一起存、恢复后带图判定。

### 2.5 ffmpeg 不再写死路径

`.wxgf`（微信 4.x 的 H.265 容器，常见于动态表情）才需要 ffmpeg；PNG/JPEG/GIF/WEBP 解密后直接可用。查找顺序：

1. 环境变量 `WXBOT_FFMPEG`
2. `config.json` 的 `media.ffmpeg`
3. 项目内 `tools\ffmpeg\ffmpeg.exe`
4. `PATH` 里的 `ffmpeg`
5. `pip install imageio-ffmpeg` 自带的静态版（`wechatauto-replica` 通常会顺带装上）

都找不到就只跳过 `.wxgf`，其余图片不受影响；`诊断.bat` 第 7 项会打印当前找到的路径。

## 5. 审查中修掉的问题

这轮自查发现并修复：

1. **待确认 id 冒充提醒 id**：`maybe_capture` 把待确认记录 id 混进了“已建提醒”列表，`accepted_hint` 按编号查提醒会撞到别的会话的提醒，把别人的提醒说成「你已经记下了」。现在双保险：不再混入 + `accepted_hint` 校验会话。
2. **模型瞎猜的时间被存成提案**：缺时间时回「对」会把编出来的「每周一 07:50」坐实。现在缺时间不存提案。
3. **新委托被当成旧答案**：等确认期间又下一单，会被套成旧委托的内容和周期。现在含委托词就按新单处理。
4. **超限图片被套情绪描述**：第 5 张以后的图走了表情分支，用“情绪”提示词描述。现在图片一律用内容描述（最多补两张，控制调用量）。
5. **图片没读出来却被当成“带图判定”**：会多问一次核对。现在 `used_images` 记录模型是否真的看到了图。
6. **答错一次就再也不问了**：`clarify_hint` 只认「还没问」状态，答非所问把状态改成「问过」后，追问句不再注入。现在两种状态都会继续问，直到问满上限。
7. **预算刚好用光仍继续塞图**（`0` 被当成“不限”）、**群背景截断先丢最新那句**、**图片全坏时发出空 parts**、**老配置缺 `media.vision` 键会让看图失效**——都已修并有回归用例。
8. **ffmpeg 硬编码**：已改为自动查找并补文档。

## 7. 已知限制

1. **图要和文字进同一轮**：微信连发会在 3.5 秒静默（最长 12 秒）内合并；图隔很久才发就是两轮，第一轮没有图可看，只能先问时间。
2. **帮不上“图像歧义”**：课表里课程色块压在分界线时，模型可能读成周二或周三；核对句就是为纠正这个准备的。
3. **澄清只能改时间/周期，不能改事**：确认期间想改内容（「不是化学前沿，是化学实验」）目前不会更新 content。
4. **成本**：一张带图委托现在会多一次“看图判定”调用（约 300~1000 token），回复侧还有内容描述 + 主模型看图；嫌贵可关 `content_desc` 或 `confirm_with_images`。
5. **老缓存**：图片内容描述按 `md5|c` 缓存；如果库里已有旧版（150 字）描述，会继续复用，需要重新生成就删掉 `media_desc` 里对应行。
6. **`.wxgf`**：没有 ffmpeg 时这类表情仍会退化成文字占位。
7. **追问有上限**：`clarify_max_asks=3`，对方一直不接话就放弃（防止无限追问）。

## 8. 升级注意

1. 重启橙子（微信小号控制台）后生效；旧库首次启动会自动加列。
2. 想在本机继续解析 `.wxgf`，任选：`pip install imageio-ffmpeg`、把 `ffmpeg.exe` 丢进 `tools\ffmpeg\`、或在 `config.json` 写 `"media": {"ffmpeg": "D:\\oopz\\ffmpeg.exe"}`（`config.json` 不进仓库）。
3. 想更省钱：`media.vision.content_desc=false`（不写图片记忆）、`proactive.reminders.confirm_with_images=false`（带图也直接建单）。
